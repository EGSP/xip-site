# xip-site

Лендинг XIP — агентской платформы. Статический сайт на Astro с компонентами Ant Design,
публикуется на GitHub Pages: <https://egsp.github.io/xip-site/>.

Страница публичная, а репозиторий продукта закрытый. Поэтому на сайте только назначение
платформы и её возможности, без устройства, конфигурации и внутренних имён.

## Устройство

| Путь | Назначение |
|---|---|
| `src/pages/index.astro` | страница: порядок разделов и то, какие компоненты получают скрипт |
| `src/data/site.ts` | все тексты страницы |
| `src/theme/antd.ts` | тема Ant Design — единый источник цветов, шрифтов и радиусов |
| `src/antd/` | общий кеш стилей antd и обёртка `AntdProvider` для React-компонентов |
| `src/layouts/Base.astro` | `<head>`, шрифты и сбор стилей antd в `<head>` |
| `src/components/` | разделы страницы |
| `src/styles/global.css` | собственные стили: сетка, отступы, типографика разделов |
| `.github/workflows/pages.yml` | сборка и публикация |

### Ant Design в статической сборке

Компоненты antd формируют CSS во время отрисовки. Каждый React-компонент на странице Astro —
отдельный корень, и без общего кеша antd вставил бы `<style>` рядом с каждым из них. Поэтому
макет сначала отрисовывает содержимое страницы (`Astro.slots.render`) с общим кешем, а затем
помещает собранные стили в `<head>`. В CSS страницы попадают стили только тех компонентов,
которые на ней есть.

Стили antd лежат в каскадном слое `antd`, а собственные стили — вне слоёв, поэтому
собственные стили переопределяют antd без повышения специфичности селекторов. Переменные
темы (`--ant-*`) объявлены на `<body>`, и собственные стили ссылаются на них, а не повторяют
значения.

Скрипт получают три компонента: вкладки возможностей и список вопросов (`client:visible`)
и шапка на узком экране (`client:media`), где она открывает боковое меню. Остальное —
разметка, отрисованная при сборке.

### Тема

`borderRadius: 1`, тёмный алгоритм, шрифты IBM Plex Sans и IBM Plex Mono. Производные радиусы
(`borderRadiusSM`, `LG`, `XS`, `Outer`) алгоритм antd при таком значении тоже делает равными 1.

## Скриншоты

Пока снимков нет, в разделе «Возможности» стоят заглушки 16:10. Чтобы заменить заглушку:

1. Положить снимок в `public/screens/`, например `public/screens/sessions.png`. Рекомендуемый
   размер — 1600 × 1000.
2. В `src/data/site.ts` у нужной вкладки указать `screen.src: '/screens/sessions.png'`.

Путь указывается от корня сайта; каталог публикации `/xip-site` подставляется сам.

## Команды

```bash
npm install
npm run dev        # сервер разработки: http://localhost:4321/xip-site/
npm run check      # проверка типов
npm run build      # сборка в dist/
npm run preview    # просмотр собранного сайта
```

Требуется Node.js 22.12 или новее; CI использует версию из `.nvmrc`.

## Публикация

Workflow `.github/workflows/pages.yml`:

- push в `main` — проверка типов, сборка и публикация на GitHub Pages;
- pull request — проверка типов и сборка без публикации;
- ручной запуск на `main` — повторная публикация.

В настройках репозитория источник Pages — **GitHub Actions** (Settings → Pages → Source).

Для собственного домена в `astro.config.mjs` меняется `site` на адрес домена и удаляется
`base`, домен указывается в Settings → Pages → Custom domain, а у регистратора добавляется
DNS-запись по инструкции GitHub.
